# Declarative

## At the limit

Everything that two languages, two peers, two documents or two runs would
each hold a copy of is stated once, as data every one of them reads. What
is derived is never written by hand; a derivation that is stale is a
failure the tree refuses, not a drift someone notices later; and a person
reading the data can tell what is declared from what was derived from it.
A family is declared and its packages, its validators and its specification
follow; the wire's cases are declared and every language's validator is
held to them; what a run produced is data and the table a reader sees is
rendered from it.

## The dimensions

- **Coverage.** Which facts are data and which are still code or prose in
  more than one place: a family, the wire's accepted and refused frames,
  the naming conventions, the promises a language makes, what a run
  produced, the shape of a document. Each fact held as code in two
  languages is a fact that will diverge.
- **Single source.** Whether any fact is held twice — declared here and
  restated there, with nothing holding the two together.
- **Automatic derivation.** Whether anything that could be rendered from
  data is written by hand: a document that restates a declaration, a table
  that restates a run, a list of names that restates a convention.
- **Staleness as failure.** Whether a derived thing that no longer matches
  its source fails a check, or merely differs until someone looks.
- **Legibility.** Whether the data is readable by a person as well as a
  tool — a declaration a consumer writes, a case a reviewer reads — and
  whether what a tool wrote is marked as the tool's, so that nobody edits
  it by hand.
- **One rule of reading.** Whether the data is read by one rule everywhere,
  or one form admits several readings and each reader picks.

## What it yields to

The boundary: what is declared is mechanism — a family, a case, a promise
— and a consumer's policy is not written into Nightseam's data. Prose,
where a rule is better said than encoded: a rule with a reason is a
sentence, and a rule with a thousand cases is a table; putting the sentence
in a table or the table in a sentence serves neither.

## What it is not

Not a language for everything: the data is small, and a mechanism is code.
Not configuration: declaring what a thing *is* differs from setting how a
thing *runs*. Not "no code": the derivations are programs, held by the
data they derive from. Not a promise that the data is stable: the
declaration language moves with the model, and rewriting the data is
cheaper than rewriting the copies it replaced.
